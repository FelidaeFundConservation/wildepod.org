# Deployment Template Files

This directory contains template files for creating custom GCP App Engine deployments.

## Overview

When deploying a custom environment using `deploy_custom.sh`, these templates show the structure needed for each configuration file. The actual files will be auto-generated by the deployment script, but you can use these as reference if manually creating or customizing deployments.

## Template Files

### 1. `TEMPLATE_config_settings.py`
Django settings file for your custom environment.
- Location: `config/settings/<env-name>.py`
- Purpose: Environment-specific Django configuration
- Replace: `<ENV_NAME>`, `<DATABASE_URL_VAR>`, `<GS_BUCKET_NAME>`

### 2. `TEMPLATE_config_wsgi.py`
WSGI application entry point.
- Location: `config/wsgi/<env-name>.py`
- Purpose: WSGI server configuration
- Replace: `<env-name>`

### 3. `TEMPLATE_app_yaml.yaml`
App Engine service configuration.
- Location: `<env-name>.yaml`
- Purpose: App Engine runtime and service settings
- Replace: `<env-name>`, `<instance-class>`

### 4. `TEMPLATE_entry_point.py`
Main application entry point.
- Location: `<env-name>.py`
- Purpose: Gunicorn entry point
- Replace: `<env-name>`

## Usage with deploy_custom.sh

The `deploy_custom.sh` script automatically generates these files:

```bash
# Script will create all 4 files for you
./deploy_custom.sh my-dev --use-existing-db --db-instance wildepoddb --full
```

Generated files:
- `config/settings/my-dev.py`
- `config/wsgi/my-dev.py`
- `my-dev.yaml`
- `my-dev.py`

## Environment Variables Required

These templates reference environment variables that must be set in Secret Manager:

### Database
- `<ENV_NAME>_DATABASE_URL` - PostgreSQL connection string
- `USE_CLOUD_SQL_AUTH_PROXY` - Use Cloud SQL Proxy (True/False)

### Storage
- `GS_BUCKET_NAME_PROD` - Google Cloud Storage bucket name

### Email
- `MAILGUN_SMTP_PASSWORD` - Mailgun SMTP password
- `EMAIL_2FA_IMAP_URL_PROD` - 2FA email IMAP URL
- `EMAIL_2FA_USER_PROD` - 2FA email username
- `EMAIL_2FA_PASSWORD_PROD` - 2FA email password

### Dropbox (Environment-Specific)
- `DROPBOX_APP_KEY_<ENV>` - Dropbox app key
- `DROPBOX_APP_SECRET_<ENV>` - Dropbox app secret
- `DROPBOX_REFRESH_TOKEN_<ENV>` - Dropbox refresh token

### Security
- `ADMIN_URL_SUFFIX` - Admin URL obfuscation suffix

### Google Cloud
- `GOOGLE_CLOUD_PROJECT` - GCP project ID

## Manual Deployment (Advanced)

If you need to manually create deployment files:

1. Copy templates and rename:
   ```bash
   cp deployment_templates/TEMPLATE_config_settings.py config/settings/my-env.py
   cp deployment_templates/TEMPLATE_config_wsgi.py config/wsgi/my-env.py
   cp deployment_templates/TEMPLATE_app_yaml.yaml my-env.yaml
   cp deployment_templates/TEMPLATE_entry_point.py my-env.py
   ```

2. Replace placeholders in each file:
   - `<env-name>` → your environment name (lowercase, hyphens)
   - `<ENV_NAME>` → your environment name (uppercase, underscores)
   - `<DATABASE_URL_VAR>` → your database URL variable name
   - `<GS_BUCKET_NAME>` → your storage bucket name
   - `<instance-class>` → App Engine instance class (F1, F2, F4, etc.)

3. Set required secrets in Secret Manager

4. Deploy:
   ```bash
   gcloud app deploy my-env.yaml
   ./post_deploy_setup.sh my-env
   ```

## Best Practices

1. **Use deploy_custom.sh**: Let the script handle file generation
2. **Don't commit custom environments**: Add to `.gitignore`
3. **Use descriptive names**: `username-dev`, `feature-test`, etc.
4. **Shared database**: Use `--use-existing-db` for cost savings
5. **Test with dry-run**: Use `--dry-run` flag first
